Frequently Asked Questions

About the project, the data, and how it works.

Is this monitoring real websites right now?

No. Live web scraping is disabled by default (ENABLE_LIVE_MONITORING=false) and the dashboard runs entirely on deterministic, synthetic demo data — 8 fictional organizations, ~130 snapshots, and 100+ generated change events across a 90-day window. The fetch/monitoring code path is fully implemented and unit-tested, but it's intentionally opt-in for anyone running this locally.

How is the "signal score" calculated?

It's a transparent, rule-based formula — not a black-box model: a base score from how much of a page's text changed, plus a category-relevance weight (pricing/funding changes score higher than cosmetic ones), minus a penalty if the change looks cosmetic. Every alert shows its full scoring breakdown on its detail page. Weights live in app/services/scoring.py and are easy to tune.

How does the classification into categories work?

Deterministic keyword/regex matching against the added and removed text, scored by match density across 11 categories (pricing, product launches, hiring, leadership, funding, partnerships, PR, regulatory, customer stories, cosmetic/noise, other). It's intentionally simple and auditable rather than an opaque ML classifier — every match is traceable to the exact keywords that triggered it.

What's the tech stack?

Python 3.12, FastAPI, SQLAlchemy 2.x + Alembic migrations, SQLite (Postgres-ready), httpx + BeautifulSoup4 for fetching/parsing, Jinja2 + Chart.js for the dashboard, pytest for testing, and Ruff/Black for linting. Full details and architecture diagrams are on the GitHub repo.

Can I run this myself or extend it?

Yes — it's fully open source. Clone the repo, copy .env.example to .env, and run make install && make migrate && make seed && make run. See the Methodology page for the design framework, or the README for full setup instructions, tests, and Docker deployment.
